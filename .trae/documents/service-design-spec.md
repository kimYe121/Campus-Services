# 《校园百事通核心服务业务流程与表单设计文档》

## 设计理念与目标
本系统的核心理念是从“人找流程”向“流程找人”转变，提供端到端的数字化闭环。所有服务不仅限于信息的简单收集，而是深入现实校园场景的具体流转节点，确保前端表单的设计能够支撑后端复杂的审批和派单逻辑，同时在用户端（学生/教工）保持界面的简洁与直观。

---

## 1. 核心业务流程设计

### 1.1 统一身份认证与登录体系 (CAS)
**现实场景分析**：
高校系统必须对接学校的统一身份认证（CAS/OAuth2），确保“校园百事通”不需要单独注册，直接通过学号/工号进行鉴权。
**业务流程闭环**：
1. **拦截与授权**：未登录用户进入小程序，拦截并重定向至“统一身份认证”登录页。
2. **账号绑定**：首次登录需输入学工号及密码，验证通过后与当前微信 OpenID 绑定，实现后续免密静默登录。
3. **身份派发**：后端返回 JWT Token 及用户基础画像（Role: Student/Teacher），前端据此动态渲染首页功能与服务大厅入口。

### 1.2 后勤报修系统 (师生共有)
**业务流程闭环**：
1. **申请**：用户通过小程序提交报修单（选择楼宇/区域、报修项目分类、拍照、描述）。
2. **调度/派单**：系统根据报修类型（水电/木工/网络等）自动派单至对应的后勤维修班组。
3. **接单与处理**：维修工（教工端）在手机端接单，到达现场后可上传维修前后的对比照片，记录耗材。
4. **完工与验收**：维修工点击完工，系统自动推送消息给报修人。
5. **评价**：报修人确认完工，并在小程序中对维修速度和服务态度进行星级评价。

### 1.3 学生请假系统 (学生专属)
**业务流程闭环**：
1. **申请**：学生填写请假类别、起止时间（精确到小时）、请假事由、离校去向及紧急联系人，并上传证明材料（如病历）。
2. **智能路由（核心逻辑）**：
   - 请假 <= 3天：系统自动流转至 **辅导员/班主任** 进行审批。
   - 请假 > 3天：系统自动流转至 **辅导员初审** -> **院系副书记/领导复审**。
3. **信息同步与消息通信**：审批一旦通过，系统自动将请假信息同步给教务系统，同时**通过小程序消息推送给该生相关课程的任课教师**。
4. **销假**：请假结束返校后，学生必须在系统点击“销假”并可附加定位信息证明已在校。

### 1.4 教师资源申请与调课服务 (教工专属)
**现实场景分析**：
教师的日常管理中，教室/会议室的借用以及调课是最高频且痛点最深的需求。调课牵涉到教务处的审批和学生的消息通知。
**业务流程闭环**：
1. **资源借用申请**：教师选择需要借用的资源类型（多媒体教室、会议室、实验室设备、车辆等），填写借用时段及用途。经过资源管理员审批后生成电子借用凭证。
2. **调停课申请**：教师在系统内选择其所带的课程表，发起“调课”或“停课”申请，填写原上课时间、期望调整后的时间和教室要求。
3. **教务审批与自动排排课冲突检测**：系统校验调整后的时间/教室是否冲突，无冲突则提交教务处审批。
4. **全员消息通信闭环**：教务处审批通过后，系统**自动向该教学班级内的所有学生的小程序端发送“调课通知”消息**，确保信息触达。

## 2. 数据库与表单字段设计 (解耦与细化)

### 2.1 登录表单 (`LoginForm`)
| 字段名称 | 控件类型 | 数据类型 | 说明 |
|---------|---------|---------|------|
| 学工号 | 输入框 | String | 10位学号或5位工号 |
| 密码 | 密码框 | String | 统一身份认证密码 |
| 微信授权 | 按钮 | Boolean | 授权获取 OpenID |

### 2.2 后勤报修表单 (`RepairForm`)
| 字段名称 | 控件类型 | 数据类型 | 说明 / 选项枚举 |
|---------|---------|---------|----------------|
| 报修区域 | 级联选择器 | String | [南区, 北区] -> [教学楼, 宿舍楼, 食堂] -> 具体楼栋 |
| 详细房号 | 输入框 | String | 如：3栋402室 |
| 报修分类 | 单选/选择器 | String | [水电维修, 门窗家具, 校园网络, 公共设施, 其他] |
| 问题描述 | 文本域 | String | 详细说明问题现象 |
| 现场照片 | 图片上传 | Array<String> | 最多上传3张图片 |
| 预约时间 | 时间选择器 | DateTime | 希望师傅上门的时间段（可选） |

### 2.3 学生请假表单 (`LeaveForm`)
| 字段名称 | 控件类型 | 数据类型 | 说明 / 选项枚举 |
|---------|---------|---------|----------------|
| 请假类型 | 选择器 | String | [病假, 事假, 公假, 产假, 其他] |
| 开始时间 | 日期时间选择 | DateTime | 精确到小时 (YYYY-MM-DD HH:mm) |
| 结束时间 | 日期时间选择 | DateTime | 精确到小时 (YYYY-MM-DD HH:mm) |
| 审批辅导员 | 选择器 | String | 下拉选择本班的辅导员/班主任 |
| 请假事由 | 文本域 | String | 详细说明原因，字数不少于15字 |
| 是否离校 | Switch开关 | Boolean | true/false |
| 离校去向 | 级联选择器 | String | 若离校为true必填，精确到省市区 |
| 证明材料 | 图片上传 | Array<String> | 病假必填（医院证明/挂号单等），事假选填 |

### 2.4 教师资源与调课申请表单 (`ResourceForm` / `CourseChangeForm`)
| 字段名称 | 控件类型 | 数据类型 | 说明 / 选项枚举 |
|---------|---------|---------|----------------|
| (调课) 原课程 | 选择器 | String | 自动拉取该教师的本学期课表 |
| (调课) 调整类型 | 单选框 | String | [调课, 停课, 补课] |
| (调课) 期望时间 | 级联选择器 | String | [第X周] -> [星期Y] -> [第Z节] |
| (资源) 资源类型 | 选择器 | String | [多媒体教室, 阶梯教室, 会议室, 实验设备] |
| (资源) 借用时段 | 时间轴选择 | Array<Time> | 渲染时间轴，用户滑动选择空闲时段 |
| (资源) 申请用途 | 文本域 | String | 借用原因说明 |

## 3. 首页 (Home) 的重构规划

1. **头部区域**：用户问候语与动态天气组件。
2. **视觉焦点（轮播图）**：展示校园风景、近期重大教务通知（支持自动轮播）。
3. **最近使用与快捷入口（核心重构）**：
   - 改为横向滑动的 **“最近访问 (Recently Used)”** 区域。系统会根据用户的点击频率自动提取最常用的 3-4 个功能（如教师的“调课申请”，学生的“宿舍报修”），提升效率。
4. **待办与进度摘要（To-Do & Progress）**：
   - 提取该用户当前状态为“待处理”或“处理中”的 **Top 2 事项**，以紧凑卡片展示。
